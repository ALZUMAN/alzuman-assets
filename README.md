# ALZUMAN — الزومان

موقع سبائك ذهب ٩٩٩.٩ لمتجر الزومان (بريدة، السعودية). موقع صفحة واحدة (single page)
بسبع مشاهد سردية مع سكرول تفاعلي، بدون أي اعتماد على ملفات فيديو.

## البنية

| مسار | الوصف |
|---|---|
| `index.html` | الصفحة الكاملة (Hero، مشهد السبيكة، العبارات، اختيار الوزن، الثقة، الفوتر) |
| `style.css` | كل الأنماط والحركات (CSS فقط، بدون مكتبات خارجية) |
| `script.js` | منطق السكرول، السعر الحي، حاسبة الوزن، الحركات التفاعلية |
| `alzuman-logo.png` | الشعار الكامل (يُستخدم في الـ Hero) |
| `alzuman-logo-light.png` | نسخة فاتحة للشعار (تُستخدم في الفوتر الكحلي) |

الموقع Static بالكامل، بدون أي build step — يُنشر على Vercel مباشرة (Framework: Other).

## فيديو مشهد السبيكة: لماذا CSS وليس فيديو حقيقي

مشهد السبيكة (المشهد الثاني) مبني بالكامل بـ CSS/SVG، **وليس بفيديو حقيقي**، لأن
ملفات `scene1-ivory.mp4` و`scene2-sand.mp4` و`scene3-gold.mp4` **الموجودة فعليًا
في هذا المستودع تالفة فعلًا** (moov atom مفقود — الحاوية تفتقد البيانات الوصفية
اللازمة لتشغيل أي فريم). تم التحقق من هذا بشكل قاطع:

- تنزيل الملفات الثلاثة مباشرة من GitHub (عبر `raw.githubusercontent.com` وعبر
  Git Blobs API بشكل منفصل — نفس النتيجة من المصدرين).
- حُسب SHA-1 الخاص بـ git object نفسه محليًا (`blob <size>\0<content>`) وطابق
  تمامًا ما يقوله GitHub API — هذا يثبت أن المحتوى الذي تم تنزيله هو **بالضبط**
  ما هو مخزَّن في المستودع، وليس تلفًا ناتجًا عن مشكلة نقل/شبكة.
- `ffmpeg -xerror` (فحص فك تشفير كامل وصارم) يفشل فورًا بـ
  `moov atom not found` / `Invalid data found when processing input` على
  الملفات الثلاثة بلا استثناء.

**ملاحظة مهمة لتفادي تكرار نفس الخطأ**: يوجد التباس سابق حصل أثناء التطوير — تم
اختبار نسخة مختلفة تحمل نفس الاسم (رفعها المستخدم مباشرة عبر المحادثة) وتبيّن
أنها سليمة، مما أدى مؤقتًا لاستنتاج خاطئ بأن ملفات المستودع سليمة أيضًا. لاحقًا
تم التحقق من نسخة المستودع تحديدًا (لا نسخة بديلة) وثبت أنها تالفة فعلًا. أي
اختبار مستقبلي لهذه الملفات **يجب أن يكون على النسخة الموجودة فعليًا في هذا
المستودع** (عبر `git show`/`raw.githubusercontent.com`/Git Blobs API)، لا على
أي نسخة محلية أو مرفوعة بنفس الاسم.

**للاستخدام مستقبلًا**: إذا توفرت نسخة سليمة من هذه المقاطع (بترميز H.264 قياسي
8-bit، `yuv420p`)، يمكن استبدال حركة CSS بعنصر `<video>` حقيقي. عند رفعها، تحقق
أولًا بـ `ffmpeg -v error -xerror -i FILE -f null -` (يجب أن يُنهي بدون أي خطأ)
قبل تضمينها بالموقع.

## أصول غير مستخدمة (مستبعدة من النشر عبر `.vercelignore`)

هذه الملفات موجودة في المستودع للمرجع فقط ولا يستخدمها الموقع، ومستبعدة من كل نشر
عبر `.vercelignore` حتى لا تُثقل حجم الـ deployment:

- `alzuman-bar.glb`, `alzuman-bar-999.glb` — موديل ثلاثي الأبعاد، للمرجع فقط.
- `scene1-ivory.mp4`, `scene2-sand.mp4`, `scene3-gold.mp4` — مقاطع فيديو **تالفة
  فعليًا** (moov atom مفقود، تأكيد مثبت أعلاه). حركة السبيكة في الموقع مبنية
  بالكامل بـ CSS/SVG بدلًا منها.
- ملفات `hf_*.mp4` — مخرجات توليد فيديو بترميز HEVC 10-bit (غير مدعوم في أغلب
  متصفحات الويب أصلًا)، وغير مستخدمة في الموقع.

## المنطق التقني المهم

- **فتح نافذة السبيكة (المشهد الثاني)**: يعتمد على `scrollY` بمنطق بكسلي ثابت
  (نسبة من ارتفاع الـ Hero عبر `offsetHeight`/`offsetTop`)، وليس على
  `getBoundingClientRect` الهش.
- **دوران السبيكة (rotateY)**: مزيج من تقدّم السكرول داخل مشهد السبيكة وحركة
  الماوس/اللمس، محدود بـ ±8 درجة.
- **السعر الحي**: يبدأ من 4183.40$ للأونصة ويتذبذب عشوائيًا ±2.4$ كل 5 ثوانٍ.
- **حاسبة الوزن**: السعر = `((سعر الأونصة + 50) / 31.1035) × 3.75 × الوزن بالغرام`،
  ويُعاد حسابه تلقائيًا مع كل تحديث لسعر الأونصة.
